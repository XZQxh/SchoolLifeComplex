# 组会汇报提纲

> 用途：把选题定案的讨论结果同步给组员，并让他们试运行演示工程。
> 建议时长：30 分钟（讲解 16 分钟 + 看演示 8 分钟 + 拍板 6 分钟）。
> 主持人：项目经理。会前把 `docs/` 与 `demo/` 发给组员，让他们先扫一眼。

---

## 一、会议目标

这次组会只解决三件事，不要扩散：

1. 让四个人对"我们到底做什么"有同一个版本的理解。
2. 让每个人亲手点一遍演示工程，知道哪些能做、哪些只是设计。
3. 把需要集体拍板的几件事定下来。

---

## 二、讲解部分

### 2.1 我们用一句话介绍项目（3 分钟）

> 面向本校在校生的校园兴趣社区：任何人可以浏览，加入后即可参与，正式社团与自发兴趣小组都能拥有自己的阵地。

差异化主张是**组织入驻**——校园里"谁代表一个正式组织发言"这件事目前没有人负责，而这正是社团最在意的。这一点是竞品分析得出的结论：今日校园占了官方数据入口，QQ 频道占了用户密度，TapTap 占了内容深度，唯一空着的位置是组织身份的确认。

要同时说清楚两个边界，避免后面反复解释：

- **服务边界**是本校全校，但**首批场景**收缩到一个具体兴趣小组。这不是矛盾：社区产品是按板块逐个冷启动的，一个板块没有内容密度，全校铺开也没用。
- 我们是**响应式 Web**，浏览器直接打开，不需要装 App、不需要小程序审核。

### 2.2 为什么砍掉了原来的一半想法（8 分钟，这部分最重要）

这是全场最容易被质疑的地方，讲的时候不要回避，直接给理由。

原始设想是"学校生活功能的统一集合体"，包含兴趣交流、通知集成、失物招领与学生会申请、大学城联动。问题在于这四块其实是**三种不同的产品形态**：

| 原模块 | 实际形态 | 价值来源 | 成败关键 |
| --- | --- | --- | --- |
| 通知集成 | 聚合器 | 数据覆盖度 | 能不能拿到官方授权 |
| 兴趣交流、社团 | 社区 | 用户密度 | 冷启动与内容审核 |
| 失物招领、学生会申请 | 事务工具 | 流程闭环 | 能不能对接真实组织流程 |
| 大学城联动 | 跨组织社区 | 多校用户密度 | 需要多校官方协作 |

三种形态拼在一起不会互相增强，只会让范围乘以三。课程要求"3~5 个问题（功能模块）"，原方案摊开至少是六个功能域，超出"规模适中"的口径。

具体到每个模块的去向：

- **学校通知集成 → 降级为板块内公告**（订阅 + 人工发布，不爬取）。理由是爬取官网与教务会直接碰到《个人信息保护法》与校方授权，这是可行性报告里最容易被老师追问的一环。降级不等于删除，它仍在需求文档里。
- **大学城联动 → 只写进前景与范围的未来展望**。跨校意味着多校组织协作与多校治理责任，单校课程项目无法验证。它的正确位置是路线图最后一步。
- **学生会申请 → 并入信息互助模块**，不再单独建设流程。
- **社团招新 → 不作为常驻模块**，它一年活跃两周，作为"活动"能力下的一个场景存在。

收敛之后剩下五个模块：身份与准入、兴趣板块、内容交流、组织与活动、信息互助。

关键取舍要说明白：**设计与文档覆盖五个模块，实现只做一条核心闭环。**

### 2.3 五个模块（3 分钟）

| 模块 | 解决什么问题 |
| --- | --- |
| 身份与准入 | 谁在发言、内容由谁负责、权限怎么划 |
| 兴趣板块 | 兴趣内容的组织与发现，让内容可搜索、可回溯 |
| 内容交流 | 发帖、评论、互动，以及举报与审核的闭环 |
| 组织与活动 | 社团与自建小组有自己的阵地，招新与活动有固定发布处 |
| 信息互助 | 失物招领与认领、校内公告 |

### 2.4 老师大概会追问什么（2 分钟）

提前把三个高概率问题的答法统一，避免组员各自理解：

**"这不就是个校园论坛吗，为什么不用 QQ 频道？"**
QQ 频道形态上接近，但没有组织身份确认——"官方社团阵地"和"任何人开的频道"长得一样。我们的差异化就是这一层认证。

**"学生为什么不用现成的产品？"**
现成产品的问题是内容留不住（群聊）或者不是校园场景（TapTap）。我们不试图取代任何官方系统，只做官方不管的学生侧连接，这一点在前景与范围报告里写成了硬边界。

**"没有任何组织入驻怎么办？"**
所以采用双通道：学生可以自由创建板块，组织认证只是加成而不是门槛。冷启动的启动条件因此从"说服组织"降回"有人愿意发帖"，后者我们自己就能做到。

## 三、现场看演示（8 分钟）

按 [演示说明](演示说明.md) 的五个场景走一遍，重点让他们看到四件事：

1. 游客能浏览，但发帖需要加入板块（权限是分层的）。
2. 待审帖子只有作者和版主看得到（审核开关是真生效的）。
3. 举报能被处置，封禁之后确实发不了言（治理闭环不是画在纸上的）。
4. 认证组织在板块上有标识（差异化主张是可见的）。

演示时主动指出哪些是**没做的**：不接官方系统、没有跨校、公告是人工发布、没有个人主页与信誉分。被问到答"这是设计范围内的取舍"，而不是"还没做"。

## 四、需要拍板的事（6 分钟）

这六件事都记录在 [决策记录](decisions-school-life-complex.md) 的待定问题里，会上逐条过：

| 编号 | 待定问题 | 谁来定 | 影响 |
| --- | --- | --- | --- |
| O1 | 首批场景用哪个具体游戏小组 | 全员 | 需求分析与竞品分析的取材落点 |
| O2 | 学校是否已有官方或第三方的学生社区 | 分工后由某人去核实 | 可行性报告的竞争结论 |
| O3 | 课程是否指定技术栈 | 项目经理下次上机时问老师 | 可行性报告的技术可行性一节 |
| O4 | 七份文档在四个人里怎么分 | 全员，本次会议必须定 | 成员表与工作量统计 |
| O5 | 是否争取一个真实社团的合作意向 | 全员 | 组织可行性的结论强度 |
| O6 | 演示形式：现场跑工程还是录屏 | 全员 | 演示工程的完成度要求 |

O4 建议当场分掉，别拖到下次。参考分法：项目经理拿需求分析 + 总体设计；一位组员拿竞品分析 + 前景与范围 + 可行性（这三份共享同一批调研材料，一个人写更快）；一位拿详细设计 + 测试报告；最后一位承接开发与演示准备。实际按每组情况调整。

## 五、组员怎么自己跑演示工程

### 方式一：连你的电脑（最快，需要同一个 Wi-Fi）

1. 你的电脑上保持 `npm run start` 运行。
2. 组员在同一局域网的浏览器里打开 `http://192.168.110.179:3100`。
3. 如果打不开，多半是 Windows 防火墙拦了入站连接，见第六章。

注意：你的电脑关机或切换网络后地址会变，这种方式只适合临时看一下。

### 方式二：各自在自己电脑上跑（推荐，能改代码）

拿到压缩包后解压，确认电脑装过 Node.js（`node -v` 能输出版本号），然后：

```bash
cd demo
npm install
npm run build
npm run start
```

浏览器打开 `http://localhost:3100`，用 `000000 / admin123` 或 `20230101 / student123` 登录。

`npm install` 需要联网下载依赖，第一次会花几分钟；之后运行不需要网络。

### 方式三：只看不跑

压缩包里的 `demo/screenshots/` 有首页、板块页、失物招领页的桌面与移动端截图，够用来理解界面。

## 六、如果局域网打不开

先确认三件事：两台电脑在同一个 Wi-Fi、你这边服务还在运行、地址里的 IP 没变过（重开终端跑一次 `ipconfig` 看 WLAN 的 IPv4 地址）。

仍然打不开就是防火墙。以管理员身份打开 PowerShell，执行一次即可：

```powershell
netsh advfirewall firewall add rule name="SLC Demo 3100" dir=in action=allow protocol=TCP localport=3100
```

演示结束后想撤销这条规则：

```powershell
netsh advfirewall firewall delete rule name="SLC Demo 3100"
```
