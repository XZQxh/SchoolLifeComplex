# 演示说明

本文档面向课程演示环节，说明演示工程的运行方式、预置账号与演示脚本。

---

## 一、运行方式

```bash
cd demo
npm install
npm run build
npm run start
```

浏览器打开 http://localhost:3100 。默认端口为 3100，若被占用可修改 `package.json` 中 `dev` 与 `start` 脚本的端口号。

开发模式（改代码即时生效）：

```bash
npm run dev
```

重置为初始演示数据：

```bash
npm run reset
```

数据文件位于 `demo/data/db.json`，首次访问时自动生成；删除后会自动重建为种子数据。

## 三、演示脚本（约 6 分钟）

### 场景一：游客与板块发现（1 分钟）

1. 不登录打开首页，展示板块列表、分类筛选与搜索 → 对应"浏览无门槛"。
2. 点开「星轨动漫社」板块，指出认证标识与"注册社团"身份 → 对应差异化主张。
3. 指出「王者荣耀开黑小组」是学生自建小组，同样可以开设板块 → 对应双通道准入。

### 场景二：发帖与审核（1.5 分钟）

1. 用 `20230103 / student123` 登录，打开「考研自习室」板块并加入。
2. 发布一条帖子，指出它进入**待审**状态（该板块开启了发帖审核）。
3. 退出登录，以游客身份刷新该板块，确认看不到这条待审帖。
4. 用 `20230101` 登录（该板块版主），在板块页点"通过"，帖子变为公开。

### 场景三：举报与治理闭环（1.5 分钟）

1. 用 `20230103` 打开一篇他人帖子，点"举报"并选择原因。
2. 用 `20230101` 打开治理台，在举报队列中看到该条举报，选择"驳回举报"，说明判定依据。
3. 再次举报同一内容，用治理台执行"封禁作者"，然后切回 `20230103` 尝试评论，确认被封禁后无法评论 → 对应"治理可闭环且确实生效"。

### 场景四：失物招领（1 分钟）

1. 在失物招领页发布一条招领信息。
2. 换另一个账号点"认领"，状态变为"已认领"；再点一次，系统拒绝重复认领。

### 场景五：组织认证（1 分钟）

1. 用普通账号在「组织入驻」页提交一个组织的入驻申请，状态为待认证。
2. 用 `000000 / admin123` 登录，在治理台认证该组织。
3. 回到该账号，在其管理的板块上认领为组织官方阵地，板块页出现认证标识。

## 四、演示前检查清单

- [ ] 已执行 `npm run build` 且构建无错误
- [ ] 已执行 `npm run reset`，数据为种子状态
- [ ] 浏览器窗口宽度足够，或提前把移动端截图放在手边
- [ ] 关闭其他占用 3100 端口的程序
- [ ] 若现场无网络，确认已提前完成 `npm install`（演示运行不需要联网）

## 五、常见问题

**端口被占用**：`npm run start` 会报端口错误。修改 `package.json` 中的端口，或先停止占用该端口的进程。

**页面打开是空白**：确认服务进程仍在运行；终端中 `✓ Ready` 出现后再访问。

**数据被测试脚本弄脏**：`node smoke-test.js` 会创建测试用的板块与账号，执行 `npm run reset` 即可恢复。

**忘记密码**：演示环境没有密码找回功能，用 `npm run reset` 重置数据即可恢复预置账号。

## 六、演示环境的边界

演示工程只覆盖五个模块的核心闭环，以下内容**没有实现**，被问到时应如实说明这是设计范围内的取舍，而不是缺陷：

- 不接入任何学校官方系统，不抓取官网与教务数据；
- 不含跨校（大学城）功能，它在前景与范围报告中作为未来展望；
- 不含通知聚合的自动抓取，公告为人工发布形态；
- 不含即时通信、图片上传、活动报名与签到；
- 不含个人主页、信誉分与校园身份认证申请入口，它们属于"仅设计"的需求；
- 会话机制未做签名与过期控制，属于演示级简化，加固清单见详细设计报告第九节。
